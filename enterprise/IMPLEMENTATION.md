# 采购场景实施与验收

## 试点边界

一个经授权的采购知识域、两个具备后台权限的不同审查账号。使用合成供应商与招标编号，真实文件保留在原知识系统；审查记录只存必要引用及摘要。
当前不自动发布采购决定，不向 ERP 写入，不宣称已验证外部文件签章。所有具备后台权限的管理员可查看当前租户审查记录，细分项目访问范围需额外授权设计。

## 操作路径

1. 在上游知识检索界面获取经授权的文件引用，人工核对版本与原文。
2. 打开后台 Procurement review，粘贴结构化要求与证据 JSON，创建草稿。
3. 作者提交。缺少必选要求证据或有效期已过时阻止流转。
4. 另一管理员批准或写明驳回原因。批准时再次检查证据有效期。
5. 查看追加式审计事件，核对操作人、版本和 payload 摘要。

| UAT | 预期 |
|---|---|
| 同一作者/请求键/相同内容重复建单 | 返回原单 |
| 同一键换内容 | 冲突，不覆盖 |
| 作者批准自己的提交 | 拒绝 |
| 两个复核人同时批准相同版本 | 仅一次状态更新成功 |
| 提交后证据过期 | 批准被阻止 |
| 驳回没有原因 | 拒绝 |
| 普通账号直接调用 API | 权限层拒绝，需部署环境复测 |

## 发布、回滚与缺口

先在预发布运行迁移和合成数据验收，再逐步开放菜单。回滚应用时保留数据库和事件表，导出必要审查数据后单独决定数据迁移。
CI 覆盖数据库和策略；完整平台启动鉴权检查、浏览器双账号操作及多租户环境迁移仍需预发布验证。审计表不提供编辑/删除 API，但数据库管理员仍有数据库权限；未宣称防篡改账本。
